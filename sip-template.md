# Sila proposal authoring template

Create a file named SIPS/sip-N.md only after the Sila publication authority has assigned the real proposal number. Replace every placeholder with an actual value. Do not invent approvals, discussion threads, creation dates, or protocol integrations.

Required metadata:

    ---
    sip: N
    title: Original Sila feature title
    description: One concise statement of the Sila-specific change.
    author: Approved Sila author
    status: Draft
    type: Standards Track
    category: Core
    created: YYYY-MM-DD
    ---

For a Meta or Informational SIP, omit category. Use discussions-to only for an existing Sila discussion. Use requires only for independently verified Sila SIP dependencies.

## Abstract

Summarize the proposed behavior.

## Specification

Define inputs, outputs, behavior, boundary conditions, and applicable Sila-native interfaces.

## Rationale

Explain the design choices and alternatives.

## Security Considerations

Identify risks, attacker capabilities, failure modes, and mitigation requirements.

## Copyright

State the rights applicable to the original Sila material.
